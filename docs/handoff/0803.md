## 2. Step 0：诊断结论（驱动重构的证据）

用 `diagnose.py`（src/ai/experiments/）分析 best_masked @ sims=400 的 20 固定 seeds：

- 灾难对局（seeds 0/3/5/11/14，final 30-54）有清晰共同模式：
  - **seed 14：铁路时代 16 连 Pass**（value 头认为没有好动作 → 搜索全面退化）
  - **seed 11：铁路时代建 10 块但 0 Sell**（运河时代分仅 4）
  - **seed 3：铁路时代 0 Build**
- 结论：**value 头崩溃 → 搜索 Q 失真 → 晚期动作退化**。与 §3.3（自对弈漂移根因）一致。
- 修正认知：**煤/铁/酒被消耗即自动翻面推进收入**（无需 Sell 操作），"翻面"不等于"卖货"。
  因此 seed 11"Sell=0 却有 6 块翻面"是消耗型翻面，非 bug。诊断只看动作分布与分数。

## 3. 新 Schema 落地清单（Step 1-3，全部测试绿）

### 3.1 `src/ai/brass_ai/net.py`（重写）
- 分叉 policy：`type_head Linear(256→7)` + `goal_head Linear(256→1316)`，合并 `logit(s)=type[t(s)]+goal[s]`
- value 头：`Linear(256→4)` 预测 4 玩家 z 向量，**去 tanh**
- `merge_logits(type, goal)`：把分叉合并回全表 logits（训练 loss / 单线程 MCTS 用）
- `slot_types()`：读 `be.slot_types`（Rust 带算术表，单一事实来源）

### 3.2 Rust 侧
- `policy.rs`：新增 `ACTION_TYPE_*` 常量 + `slot_type(slot)`（7 类型带算术）+ `slot_types()` 全表数组
- `pymod.rs`：`m.add("slot_types", policy::slot_types())`；`search_net` docstring 更新
- `nn_mcts.rs` `flush_net`：**每 request 只发 1 行**（当前玩家视角）→ 收 `(type[7], goal[1316], value[4])`；
  先验 = 对 legal_slots 逐槽 `type[t]+goal[s]` 后 softmax；MaxN 直接用 4 向量（不再 4 行取对角）
- `RequestKind::Expand` 删除 `policy_player` 字段（视角=state 当前玩家）

### 3.3 训练管线
- `selfplay.py`：`Sample.value` 改为 `(4,)` z 向量；`play_game_with_roles(roles, cfg, collect)` 支持按座位收集
- `mp_selfplay.py`：pack/unpack value 改 `(n,4)`；worker 支持 matchmaking（learner 座位 + 历史池）
- `train.py`：`compute_loss` 用 `merge_logits` + masked CE；value 改 4 值 MSE；`_to_batch` stack
- `mcts.py`（单线程参考实现）：`_expand`/`_eval_value` 改单视角 + merge

### 3.4 验证
- engine pytest 14 + AI pytest 10 + `cargo test` 全绿
- 搜索冒烟：0.35ms/sim（CPU）@sims=200，best 合法

## 5. Step 5：benchmark 门控自对弈 + matchmaking（就绪）

### 代码
- `brass_ai/evaluate.py`：新增 `benchmark_mcts_vs_heuristic(net, sims, games, device, ...)` → dict
  （win_rate + mean/median VP），**决策级门控的唯一标准**
- `experiments/benchmark.py`：瘦身为调用共享函数
- `mp_selfplay.py`：`_worker_fn` 支持 `(weights, pool_weights, games, sims, seed_offset, mcts_cfg, temperature, mm_prob)`；
  `SelfPlayPool.generate(... mm_pool, mm_prob)`；learner 座位轮转、对手从池中按 mm_prob 抽样
- `train_mp.py`：重写为 benchmark 门控 + matchmaking
  - 门控：`--eval_every` 次跑 `benchmark_mcts_vs_heuristic`；接受标准 = 胜率 ≥ best（平手比 median VP）
  - matchmaking：`--mm_prob`（对手座位用历史池的概率）+ `--pool_size`（池上限）；池 = 起始 ckpt + 每次接受的新 best
  - 回滚：胜率退化时 `net.load_state_dict(best_state)`

### 短训冒烟（iters=4, sims=150, bench=12 局）
```
iter 0 w=0.33 (new best) → iter 1 w=0.25 (reverted) → iter 2 w=0.42 (new best) → iter 3 w=0.25 (reverted)
```
门控逻辑正确工作。注意小样本（12 局）胜率波动大（0.33↔0.42），**正式跑必须 `--bench_games 20`**。

## 10. 接手注意事项

1. **决策必须用 `benchmark.py` / `benchmark_mcts_vs_heuristic`（≥20 局固定 seeds）**；小样本只冒烟
2. 新契约下 `net(batch)` 返回 3 元组 `(type, goal, value)`；`net.policy_value` 同；单线程 MCTS 用 `merge_logits`
3. 改 Rust 后必须 `maturin develop` + `cargo test`
4. 长任务带进度/ETA；`SelfPlayPool` 退出会 join，异常时残留 worker 用 `taskkill //F //PID`
5. 参考项目 `reference/` 只读；规则分歧按 AGENTS.md §7 交用户裁决
