## 项目概览

纯 HTML/CSS/JS 的数字版《伯明翰》（无构建、无依赖、无框架）。约 5900 行，是本项目 **规则引擎的黄金参考**。
用浏览器打开 `index.html` 即可本地跑起来（或 `python3 -m http.server`）。

## 关键实现位置

### 规则数据 → `js/gameData.js`
- 城市节点、连接（运河/铁路）、城市槽位（可建产业类型）
- 卡牌构成（地点牌/工业牌/万用牌）
- 市场轨道（煤/铁/棉/陶）、商家点位
- 各产业各等级的 **费用（£ / 煤 / 铁）、收入、VP** —— 所有数值的源头

### 网络寻路 → `js/gameState.js`
- 如何判断"网络是否连通到某城市 / 市场 / 商家"
- 连通性与煤供给的绑定逻辑
- 建议：Rust 里用图 + 增量 BFS / 并查集重写，这里读的是语义

### 合法性判定 → `js/gameLogic.js`
- 每个行动的先决条件、资源校验、卡牌校验
- **`getDisabledReason()`**：返回"为什么不能做"——等于一份完整的规则校验清单，翻译成 Rust 时按这条函数逐条对照

### 启发式 AI → `js/aiPlayer.js`
- `vpEquivalent()`：把 VP/收入/资金/灵活性统一折算成 VP 当量分数
- `cardUsefulness()`：卡牌保留价值评估（Scout/弃牌决策）
- `estimateFlipProbability()`：翻面概率估计
- 结论：**阶段 1 的"规则 AI"可直接借鉴此文件**，比纯随机强得多

## AIPlayer 评估函数原理（已翻译至 Rust `src/engine/src/heuristic_ai.rs`）

> 性质：**纯 1-ply 贪心启发式**，无前瞻搜索、无学习。每回合枚举合法动作 → 各算一个 VP 等价分 → 取最高。

### 统一评分框架
```
score = vp*1.0 + income*incomeWeight + money*0.12 + flex*0.8
incomeWeight = 0.35 * (剩余轮数 / 5)     # 回合越少收入越不值钱（核心洞见）
剩余轮数 = drawDeck剩余 / 玩家人数, clamp[1,10]
```

### 各动作要点
| 动作 | 评分核心 | 关键设计 |
| --- | --- | --- |
| Build | `vp*flipProb + income*flipProb*w + 花费*(-0.12)` + 网络加成 | flipProb：煤/铁 0.7，啤酒 0.5，可售 0.6(+0.2 已连通商家, -0.3 剩<2轮)；邻近自己连接加分；资源自足 +0.15/块；未建邻接连接 +0.1/条 |
| Network | 手牌地点卡新入网数量 + 连到新商家 1.5 | 纯修路不建厂 → -1.0；探索奖励 `max(0, 1.6 - 已建*0.3)` |
| Develop | 紧迫度(运河专属 2.0 / 其它 0.5) + 解锁价值 0.3*等级 | 付得起 2 铁就开发 2 个 |
| Sell | 板块 vp + income*0.3 + 商家啤酒 bonus | **一次卖全部可售目标**；优先喝商家桶（白拿 bonus） |
| Loan | 现金不足 +4.0；钱太多 -2.5；收入≤-5 -2.5 | 贷款本身不直接加分，靠救急信号 |
| Scout | 按"卡牌有用度"弃 3 张最没用的 | 万用 5、地点 2、产业 1.5、死牌 0 |
| Pass | 固定 -0.5 | 永远兜底 |

### 可复用特征（后续 MCTS/深度网络的评估头可直接沿用）
1. **收入的时间价值衰减**（incomeWeight 随轮数下降）
2. **网络的"手牌激活价值"**（新入网地点卡数量）
3. **贷款的救急/充裕双向惩罚**
4. **翻面概率估计**（资源/可售/啤酒的类型差异）

## 借鉴策略（给 Rust 引擎阶段）

1. 先读 `gameData.js`，把数据结构定义成 Rust 常量（可用脚本或手工翻译）
2. 再读 `gameLogic.js` 的 `getDisabledReason()`，逐条实现合法性判定
3. 用 `aiPlayer.js` 的权重思想写启发式 AI 作为 Baseline
4. 用 npm 化/手工对比：JS 输出与 Rust 输出对同一盘面跑随机对弈做一致性校验

> 注意：该项目是 2-4 人 hotseat 逻辑，未含 TTS 相关代码。
